# 🖥️ Удалённое управление ПК через Android

Включить, выключить, перезагрузить или усыпить домашний компьютер с телефона — из любой точки мира.
Публичный IP, проброс портов и платные подписки не нужны: работают Wake-on-LAN, SSH и Tailscale.

---

## 🧭 Как это устроено и кто за что отвечает

```
[Основной телефон] ──Tailscale──▶ [Домашний телефон · реле] ──домашний Wi-Fi──▶ [ПК]
      пульт                              руки дома                              цель
```

| Устройство | Роль | Что на нём настраивается | Что перестанет работать, если сломать |
|---|---|---|---|
| 🖥️ **ПК (Windows)** | то, чем управляют | OpenSSH Server, Wake-on-LAN в BIOS и в драйвере сетевой карты | ничего не получится вообще |
| 📱 **Домашний телефон** — «реле» | руки в домашней сети: будит ПК и служит трамплином для SSH | Termux, `sshd` на порту **8022**, скрипт `~/wol.sh`, Tailscale | `wake`, а также `shutdown` / `reboot` / `sleep` (они идут **через** реле) |
| 📱 **Основной телефон** — «клиент» | пульт: с него вы нажимаете команды | Termux, этот репозиторий, SSH-ключ, Tailscale | нажимать нечего |
| 🌐 **Tailscale** | приватная сеть между двумя телефонами | один и тот же аккаунт на обоих | телефоны не видят друг друга |

### Почему нужен именно второй телефон

Магический пакет Wake-on-LAN действует только внутри локальной сети — роутер не пропускает его из интернета.
Значит «нажать кнопку питания» должен кто-то, кто физически дома: это и есть реле.
Остальные команды идут по SSH по цепочке `клиент → реле → ПК`.

### Кто куда подключается

```
wake:      клиент ──SSH :8022──▶ реле ──UDP :9 (broadcast)──▶ ПК   (просыпайся)
shutdown:  клиент ──SSH :8022──▶ реле ──SSH :22──▶ ПК             (выключись)
reboot:    клиент ──SSH :8022──▶ реле ──SSH :22──▶ ПК             (перезагрузись)
sleep:     клиент ──SSH :8022──▶ реле ──SSH :22──▶ ПК             (усни)
```

## 📋 Что понадобится

| Компонент | Требования |
|---|---|
| 🖥️ **ПК** | Windows 10/11, поддержка Wake-on-LAN, **проводное** подключение к роутеру |
| 📱 **Домашний телефон** | Android, тот же Wi-Fi, что у ПК, всегда включён и в розетке (он работает круглосуточно) |
| 📱 **Основной телефон** | Android, с него идёт управление (может быть где угодно) |
| 🌐 **Аккаунт Tailscale** | бесплатный, один на оба телефона |
| 🔐 **Пароль на учётке Windows** | обязателен: SSH не пускает учётки без пароля |

## ✅ Как проверять, что всё работает

Три уровня проверки — от простого к сложному. Все команды выполняются **на основном телефоне в Termux**, кроме помеченных «на ПК» / «на реле».

### Уровень 1 · Реле на связи

```bash
ssh -p 8022 <RELAY_USER>@<RELAY_IP> 'echo OK'
```
**Ожидается:** `OK`.

- Попросило пароль → связь есть, но ключи ещё не настроены (шаг [3.3](docs/03-main-phone-client.md)).
- `Connection timed out` → Tailscale или `sshd` на реле (шаг [2.4](docs/02-home-phone-relay.md)).

### Уровень 2 · ПК доступен через реле

```bash
ssh -t -p 8022 <RELAY_USER>@<RELAY_IP> "ssh <PC_USER>@<PC_IP> 'hostname'"
```
**Ожидается:** имя вашего ПК.

Это главная проверка: она доказывает, что вся цепочка `клиент → реле → ПК` рабочая, а значит команды `shutdown` / `reboot` / `sleep` тоже выполнятся.

### Уровень 3 · ПК просыпается

1. Выключите ПК полностью (**не** «спящий режим»).
2. На клиенте: `wake`
3. Подождите 30–60 секунд — столько грузится Windows.
4. Повторите проверку уровня 2 → должен ответить `hostname`.

> 💡 Выключенный ПК **не пингуется** — это норма, брандмауэр Windows блокирует ICMP. Ориентируйтесь на SSH, не на `ping`.

### Сводный чек-лист

| # | Проверка | Команда | Ожидаемый результат |
|---|---|---|---|
| 1 | Служба SSH на ПК *(на ПК)* | `Get-Service sshd` | `Status: Running` |
| 2 | IP и MAC ПК известны *(на ПК)* | `ipconfig /all` | значения записаны в `PC_IP` / `PC_MAC` |
| 3 | Tailscale на реле поднят *(на реле)* | `tailscale ip -4` | `100.x.y.z` |
| 4 | `sshd` на реле слушает порт *(на реле)* | `ss -tlnp \| grep 8022` | строка с `:8022` |
| 5 | Реле отвечает с клиента | `ssh -p 8022 <RELAY_USER>@<RELAY_IP> 'echo OK'` | `OK` |
| 6 | ПК доступен через реле | см. уровень 2 | имя ПК |
| 7 | `wol.sh` лежит на реле *(на реле)* | `ls -l ~/wol.sh` | права `-rwx...` |
| 8 | ПК просыпается | `wake` + пауза | SSH отвечает |

## 🚀 Быстрый старт (когда всё уже настроено)

Нужен, если переустанавливаете Termux или ставите проект на новый телефон.
ПК и реле уже настроены по частям 1–2; на телефоне есть Tailscale и Termux (F-Droid).

```bash
pkg update -y && pkg install -y openssh git
git clone https://github.com/BobLoTiK/WOL ~/pc-remote-control
cd ~/pc-remote-control
cp config/config.example.sh config/config.sh
nano config/config.sh            # свои IP/MAC/юзеров
chmod +x scripts/relay/*.sh scripts/client/*.sh config/*.sh
```

Дальше: SSH-ключи и алиасы — [часть 3](docs/03-main-phone-client.md) и [часть 4](docs/04-scripts.md).

## 🗂️ Что лежит в проекте

```
pc-remote-control/
├── config/
│   ├── config.example.sh   ← шаблон с плейсхолдерами (можно коммитить)
│   └── config.sh           ← ваши реальные IP/MAC/логины (в .gitignore)
├── scripts/
│   ├── relay/wol.sh        ← отправляет magic packet (работает на реле)
│   └── client/*.sh         ← wake / shutdown / reboot / sleep (работают на клиенте)
└── docs/                   ← инструкции по частям
```

| Файл | Где работает | Зачем |
|---|---|---|
| `config/config.sh` | клиент | единственное место, где хранятся ваши адреса и логины |
| `scripts/relay/wol.sh` | **реле** (`~/wol.sh`) | собирает и отправляет магический пакет в домашнюю сеть |
| `scripts/client/wake_pc.sh` | клиент | просит реле разбудить ПК |
| `scripts/client/shutdown_pc.sh` | клиент | выключает ПК через реле |
| `scripts/client/reboot_pc.sh` | клиент | перезагружает ПК через реле |
| `scripts/client/sleep_pc.sh` | клиент | отправляет ПК в сон через реле |
