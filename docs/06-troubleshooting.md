# ⚠️ Часть 6 — Диагностика: где именно порвалось

Система состоит из трёх звеньев, и почти любая поломка — это одно из них:

```
клиент ──①──▶ реле ──②──▶ ПК ──③(WOL)──▶ «проснись»
```

Проверяйте **по порядку**, начиная с ①. Не переходите к следующему звену, пока не работает предыдущее.

---

## A · Клиент не видит реле (①)

**Симптом:** `ssh -p 8022 ... 'echo OK'` даёт `Connection timed out` / `Connection refused` / `No route to host`.
Значит `wake`, `shutup`, `reboot`, `sleep` не работают **все** — они идут через реле.

| Проверка | Где | Что должно быть |
|---|---|---|
| `tailscale status` | клиент | реле в списке, не `offline` |
| `tailscale ip -4` | реле | адрес совпадает с `RELAY_IP` |
| `ss -tlnp \| grep 8022` | реле | строка с `:8022`; пусто → выполните `sshd` |
| `whoami` | реле | совпадает с `RELAY_USER` |
| `passwd` задан? | реле | если не задан — SSH не пустит |

Частые причины:

| Причина | Решение |
|---|---|
| Termux закрыт, `sshd` не запущен | в Termux на реле: `sshd` + `termux-wake-lock` |
| Android выгрузил Termux | «Батарея → Без ограничений» для Termux и Tailscale |
| Телефон перезагрузился | настроить автозапуск — [часть 2.4](02-home-phone-relay.md) |
| Tailscale на разных аккаунтах | войти в один и тот же аккаунт на обоих телефонах |
| На телефоне включён другой VPN | Tailscale использует VPN-слот Android: отключите сторонний VPN, иначе Tailscale не поднимется |
| Сменился Tailscale-IP реле | обновить `RELAY_IP` в `config/config.sh` |

---

## B · Реле не доходит до ПК (②)

**Симптом:** реле отвечает (`OK`), но проверка через реле даёт `Connection timed out` или `Permission denied`.
Ломаются `shutup` / `reboot` / `sleep`; `wake` при этом может работать.

```bash
# диагностика одной командой
ssh -t -p 8022 <RELAY_USER>@<RELAY_IP> "ssh -v <PC_USER>@<PC_IP> 'hostname'"
```

| Причина | Как проверить | Решение |
|---|---|---|
| ПК выключен или спит | `hostname` не отвечает | сначала `wake` |
| Неверный `PC_IP` | на ПК: `ipconfig` | вписать актуальный IPv4 в конфиг |
| `sshd` на ПК не запущен | на ПК: `Get-Service sshd` | `Start-Service sshd` + `Automatic` |
| Брандмауэр блокирует порт 22 | с другого ПК в сети: `ssh <PC_USER>@<PC_IP>` | создать правило (часть 1.4) |
| Неверный пароль / логин | на ПК: `whoami` | поправить `PC_USER` |
| `Host key verification failed` | ключ ПК сменился (переустановили Windows) | на реле: `ssh-keygen -R <PC_IP>` |
| Команда «проходит», но ничего не делает | потерян флаг `-t` | используйте скрипты из репозитория как есть |

---

## C · ПК не просыпается (③)

**Симптом:** `wake` печатает `Magic packet sent to ...`, но ПК не включается. Остальные команды работают.

Это **не** проблема телефонов — пакет ушёл. Проблема на стороне ПК/BIOS. Проверяйте по списку:

| # | Что проверить | Как | Правильное состояние |
|---|---|---|---|
| 1 | `ErP` / `ErP Ready` | BIOS | **Disabled** |
| 2 | `Wake on LAN` / `Power On By PCI-E` | BIOS | **Enabled** |
| 3 | «Быстрый запуск» Windows | Панель управления → Электропитание | **выключен** |
| 4 | `Wake on Magic Packet` | Диспетчер устройств → адаптер → Дополнительно | **Enabled** |
| 5 | Галки в «Управление электропитанием» адаптера | там же | обе включены |
| 6 | MAC в `~/wol.sh` на реле | `head -5 ~/wol.sh` | совпадает с `ipconfig /all` |
| 7 | `PC_BROADCAST` | `config/config.sh` | первые 3 числа IP + `.255` |
| 8 | Кабель, а не Wi-Fi | — | Ethernet обязателен |
| 9 | Как выключали | меню «Завершение работы» | полное выключение, не гибернация |

> 💡 Быстрая проверка «а пакет вообще правильный?»: запустите `~/wol.sh` на реле при **включённом** ПК, затем на ПК посмотрите в «Монитор ресурсов» или просто убедитесь, что MAC в выводе скрипта совпадает с `ipconfig /all`.

## D · Ключи и права (просит пароль / `Permission denied (publickey)`)

| Симптом | Причина | Решение |
|---|---|---|
| Просит пароль при каждом `wake` | ключ не установлен или не принят | пройти [часть 3.3](03-main-phone-client.md) заново |
| `Permission denied (publickey)` | в `authorized_keys` вставлен приватный ключ или строка с переносом | вставить `id_rsa.pub` **одной строкой** |
| Всё равно не пускает | права файлов | на реле: `chmod 700 ~/.ssh && chmod 600 ~/.ssh/authorized_keys` |
| После переустановки Termux перестало работать | ключ хоста изменился | `ssh-keygen -R "[<RELAY_IP>]:8022"` |
| Ключ есть, но пароль спрашивает по-прежнему | Termux не видит `~/.ssh` (неверный пользователь) | проверьте `whoami` и что файл лежит в его домашней папке |

---

## E · Известные ограничения (запомнить сразу)

| # | Ограничение | Что делать |
|---|---|---|
| 1 | Порт SSH в Termux — **8022**, не 22 | не меняйте `RELAY_SSH_PORT` |
| 2 | Права `authorized_keys` должны быть `600`, `.ssh` — `700` | иначе SSH молча игнорирует ключ |
| 3 | ПК не пингуется, даже когда включён | диагностируйте по SSH, а не `ping` |
| 4 | Сторонний VPN на телефоне конфликтует с Tailscale | отключить второй VPN |
| 5 | Вложенный SSH без `-t` ничего не выполняет | в скриптах флаг уже стоит — не убирайте |
| 6 | Android может «убить» Termux | «Батарея → Без ограничений» + автозапуск |
| 7 | После `shutdown /s /t 0` отменить выключение нельзя | при необходимости `/t 60` и `shutdown /a` |

## 🔎 Универсальный алгоритм

1. **Реле отвечает?**
   ```bash
   ssh -p 8022 <RELAY_USER>@<RELAY_IP> 'echo OK'
   ```
   Нет → раздел **A**.

2. **Реле видит ПК?**
   ```bash
   ssh -t -p 8022 <RELAY_USER>@<RELAY_IP> "ssh <PC_USER>@<PC_IP> 'hostname'"
   ```
   Нет → раздел **B**.

3. **ПК просыпается?** Выключите ПК, выполните `wake`, подождите минуту, повторите п.2.
   Пакет ушёл, но ПК молчит → раздел **C**.

4. **Просит пароль?** → раздел **D**.

5. **Скрипт ведёт себя странно** — смотрите, что он делает по шагам:
   ```bash
   bash -x ~/pc-remote-control/scripts/client/wake_pc.sh
   ```

> 💡 Правило: если **проверка 1** проходит, а **проверка 2** — нет, проблема в ПК или адресах, а не в телефонах.
> Если проверка 1 не проходит — проблема в сети/Tailscale/Termux, ПК тут ни при чём.
