# 📱 Часть 3 — Основной телефон (клиент)

> **Где:** на основном телефоне — том, с которого вы будете управлять (он может быть где угодно).
> **Сколько времени:** ~15 минут.
> **Что должно получиться:** на телефоне лежит проект с заполненным конфигом, и вы заходите на реле по SSH **без пароля**.

К этому шагу часть 1 (ПК) и часть 2 (реле) должны быть выполнены: реле отвечает на `ssh -p 8022 ... 'echo OK'` с паролем.

---

## 3.1 · Termux и Tailscale

1. **Termux** — из F-Droid (не из Play Store).
2. **Tailscale** — войдите в **тот же** аккаунт, что на реле, и включите VPN.

Установите пакеты в Termux:
```bash
pkg update -y && pkg install -y openssh git
```

Проверьте, что телефон видит реле:
```bash
tailscale status
```
В списке должна быть строка с домашним телефоном (его имя модели) и его адресом `100.x.y.z`.

---

## 3.2 · Клонируем проект и заполняем конфиг

```bash
git clone https://github.com/BobLoTiK/WOL ~/pc-remote-control
cd ~/pc-remote-control
cp config/config.example.sh config/config.sh
nano config/config.sh
```

Файл `config/config.sh` — **единственное** место, где хранятся ваши данные. Все скрипты читают его.

### Что вписать в каждую переменную

| Переменная | Что это | Где взять значение | Пример |
|---|---|---|---|
| `RELAY_USER` | логин в Termux на домашнем телефоне | на реле: `whoami` | `u0_a222` |
| `RELAY_IP` | адрес реле в Tailscale | на реле: `tailscale ip -4` | `100.65.156.38` |
| `RELAY_SSH_PORT` | порт SSH на реле | всегда `8022` | `8022` |
| `PC_USER` | логин Windows на ПК | на ПК: `whoami` в `cmd` | `максим` |
| `PC_IP` | адрес ПК в домашней сети | на ПК: `ipconfig /all` → IPv4 | `192.168.1.55` |
| `PC_MAC` | MAC Ethernet-адаптера ПК | на ПК: `ipconfig /all` → Физический адрес | `10-FF-E0-90-FC-7D` |
| `PC_BROADCAST` | широковещательный адрес подсети | первые 3 числа `PC_IP` + `.255` | `192.168.1.255` |

**Как проверить, что вписали верно:** после сохранения выполните
```bash
source config/config.sh
echo "$RELAY_USER@$RELAY_IP:$RELAY_SSH_PORT / $PC_USER@$PC_IP / $PC_MAC"
```
Должна вывестись ровно та строка, которую вы ожидаете (проверьте, что нет лишних пробелов и кавычек).

> ⚠️ `config/config.sh` в репозиторий **не попадает** (он в `.gitignore`) — ваши адреса останутся локальными.
> Если файл изменили позже — скрипты подхватят новое значение автоматически, ничего перезапускать не нужно.

## 3.3 · Беспарольный доступ на реле (SSH-ключи)

Без этого каждая команда будет спрашивать пароль — а `wake` через реле спрашивает его дважды. Ключи решают это за минуту.

**Шаг 1. На клиенте создайте ключ:**
```bash
ssh-keygen -t rsa -b 4096
```
Три раза нажмите `Enter` (путь по умолчанию, без пароля на ключ). Появятся `~/.ssh/id_rsa` и `~/.ssh/id_rsa.pub`.

**Шаг 2. Посмотрите публичный ключ:**
```bash
cat ~/.ssh/id_rsa.pub
```
Скопируйте **всю** строку — она начинается с `ssh-rsa AAAA...` и заканчивается вашим `user@host`.

**Шаг 3. На реле** (зайдите в Termux на домашнем телефоне и наберите вручную, либо подключитесь по SSH):
```bash
mkdir -p ~/.ssh
nano ~/.ssh/authorized_keys
```
Вставьте скопированную строку. **Важно:** она должна быть **одной строкой** без переносов. Сохраните (`Ctrl+O`, `Enter`, `Ctrl+X`).

**Шаг 4. Права на реле** (иначе SSH проигнорирует ключ):
```bash
chmod 700 ~/.ssh
chmod 600 ~/.ssh/authorized_keys
```

**Шаг 5. Проверьте с клиента:**
```bash
ssh -p 8022 <RELAY_USER>@<RELAY_IP> 'echo OK'
```
Ожидается `OK` **без запроса пароля**. Если пароль всё ещё спрашивает — смотрите раздел «Если не получилось».

> 💡 Ключ нужен только от клиента к реле. Второй переход (`реле → ПК`) по умолчанию идёт **по паролю Windows** — он будет спрашиваться при каждой команде `shutup` / `reboot` / `sleep`.
> Чтобы убрать и его (необязательно): создайте на ПК `C:\Users\<PC_USER>\.ssh\authorized_keys`, вставьте ту же строку ключа **одной строкой** и сохраните в UTF-8 без BOM.
> ⚠️ Если `PC_USER` входит в группу «Администраторы», Windows читает не пользовательский файл, а `C:\ProgramData\ssh\administrators_authorized_keys` — ключ кладите туда, а права выставите в PowerShell от админа:
> ```powershell
> icacls "C:\ProgramData\ssh\administrators_authorized_keys" /inheritance:r /grant "Administrators:F" /grant "SYSTEM:F"
> ```

## ✅ Проверка

**1. Реле на связи (без пароля):**
```bash
ssh -p 8022 <RELAY_USER>@<RELAY_IP> 'echo OK'
```
→ `OK`

**2. Вся цепочка до ПК:**
```bash
ssh -t -p 8022 <RELAY_USER>@<RELAY_IP> "ssh <PC_USER>@<PC_IP> 'hostname'"
```
→ имя компьютера (может спросить пароль Windows; при первом входе — `yes` на отпечаток ключа ПК)

> 🔑 **Проверка №2 — самая важная.** Если она проходит, значит `shutdown` / `reboot` / `sleep` точно сработают: они делают ровно то же самое.
> Просыпание (`wake`) проверяется только на выключенном ПК — это часть 5.

---

## ❌ Если не получилось

| Симптом | Причина и решение |
|---|---|
| `Permission denied (publickey)` | ключ вставлен не той строкой/с переносом, либо права не `600`/`700` |
| Всё равно спрашивает пароль | проверьте, что вставили **`.pub`** (публичный) ключ, а не приватный `id_rsa` |
| `Host key verification failed` | сменился ключ реле (переустановили Termux): `ssh-keygen -R "[<RELAY_IP>]:8022"` и подключитесь заново |
| `ssh: Could not resolve hostname` | ошибка в `RELAY_IP` — сверьте с `tailscale ip -4` на реле |
| `Connection timed out` до реле | Tailscale на клиенте выключен, или телефон-реле спит |
| До реле доходит, а до ПК нет | часть 1: служба `sshd` на ПК, ошибка в `PC_IP`, или ПК в другой сети |
