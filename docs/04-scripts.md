# 📜 Часть 4 — Скрипты управления

> **Где:** всё, кроме `wol.sh`, работает **на основном телефоне** (клиенте).
> **Что должно получиться:** четыре команды — `wake`, `shutup`, `reboot`, `sleep`, — каждая без пароля и с понятным результатом.

Все клиентские скрипты устроены одинаково: читают `config/config.sh` → проверяют, что реле отвечает → отправляют команду. Поэтому если сломалось — почти всегда дело в конфиге или в реле, а не в самом скрипте.

## 4.1 · Что делает каждый скрипт

| Файл | Где работает | Цепочка действий | Что вы увидите |
|---|---|---|---|
| `scripts/relay/wol.sh` | **реле** | собирает магический пакет из MAC и шлёт broadcast на UDP :9 | `Magic packet sent to XX-XX-...` |
| `scripts/client/wake_pc.sh` | клиент | проверяет реле → просит реле выполнить `~/wol.sh` | `Magic packet sent to ...` |
| `scripts/client/shutdown_pc.sh` | клиент | проверяет реле → `ssh` на ПК → `shutdown /s /t 0` | ничего (ПК выключается) |
| `scripts/client/reboot_pc.sh` | клиент | проверяет реле → `ssh` на ПК → `shutdown /r /t 0` | ничего (ПК перезагружается) |
| `scripts/client/sleep_pc.sh` | клиент | проверяет реле → `ssh` на ПК → `rundll32.exe powrprof.dll,SetSuspendState 0,1,0` | ничего (ПК уходит в сон) |

## 4.2 · Как читать скрипт (на примере `wake_pc.sh`)

```bash
#!/data/data/com.termux/files/usr/bin/bash
source "$(dirname "$0")/../../config/config.sh"

if ssh -p "$RELAY_SSH_PORT" -o ConnectTimeout=5 "$RELAY_USER@$RELAY_IP" 'echo OK' > /dev/null 2>&1; then
  ssh -p "$RELAY_SSH_PORT" "$RELAY_USER@$RELAY_IP" '~/wol.sh'
else
  echo '❌ Домашний телефон не отвечает'
  exit 1
fi
```

| Строка | Что делает |
|---|---|
| `source .../config.sh` | подставляет ваши адреса; путь считается относительно самого скрипта, поэтому запускать можно из любой папки |
| `if ssh ... 'echo OK'` | «пробный стук»: за 5 секунд выясняет, жив ли реле. Без него вы бы ждали полный таймаут SSH |
| `ssh ... '~/wol.sh'` | просит реле выполнить скрипт пробуждения |
| `else ... exit 1` | печатает ошибку и возвращает ненулевой код (чтобы сбой было видно в скриптах и циклах) |

**Отладка:** если что-то не работает, запустите с трассировкой — Termux покажет каждую выполняемую команду с подставленными значениями:
```bash
bash -x scripts/client/wake_pc.sh
```

> ⚠️ Флаг `-t` в `shutdown` / `reboot` / `sleep` **обязателен**: он создаёт псевдотерминал. Без него вложенный SSH молча ничего не выполнит.

## 4.3 · Алиасы — короткие команды

Добавьте в `~/.bashrc` на клиенте:

```bash
PROJ=~/pc-remote-control
echo "alias wake='bash $PROJ/scripts/client/wake_pc.sh'"      >> ~/.bashrc
echo "alias shutup='bash $PROJ/scripts/client/shutdown_pc.sh'" >> ~/.bashrc
echo "alias reboot='bash $PROJ/scripts/client/reboot_pc.sh'"   >> ~/.bashrc
echo "alias sleep='bash $PROJ/scripts/client/sleep_pc.sh'"     >> ~/.bashrc
source ~/.bashrc
```

**Проверка, что алиасы встали:**
```bash
type wake
```
Ожидается: `wake is aliased to 'bash /data/data/com.termux/files/home/pc-remote-control/scripts/client/wake_pc.sh'`

> 💡 `reboot` и `sleep` — имена стандартных Linux-команд. Алиас перекрывает их только в вашей интерактивной сессии Termux (полезно: `reboot` теперь перезагружает ПК, а не телефон). Если такое поведение неудобно — назовите иначе: `pc-reboot`, `pc-sleep`.

## 4.4 · Безопасный порядок первого запуска

Не начинайте с `shutup` — иначе не поймёте, что именно не работает. Порядок такой:

| Порядок | Команда | Что проверяет | Как убедиться, что сработало |
|---|---|---|---|
| 1 | `wake` (ПК **включён**) | что реле на связи и скрипт доходит до него | `Magic packet sent to ...` |
| 2 | `sleep` | цепочку `реле → ПК` | ПК ушёл в сон, SSH перестал отвечать |
| 3 | `wake` | что из сна ПК встаёт | SSH снова отвечает через 10–30 с |
| 4 | `reboot` | команду перезагрузки | SSH пропал и вернулся через 1–2 мин |
| 5 | `shutup` | команду выключения | ПК выключился, SSH не отвечает |
| 6 | `wake` | **главную** функцию — пробуждение из выключенного | SSH отвечает через 30–60 с |

> ⏱️ Ориентиры: из сна — 10–30 секунд, после полного выключения — 30–60 секунд, после перезагрузки — 1–2 минуты.

## 4.5 · Права на исполнение и Git

В репозитории скрипты уже помечены как исполняемые (`100755`), поэтому после `git clone` работает сразу.

Проверить на телефоне:
```bash
ls -l scripts/client/wake_pc.sh    # → -rwxr-xr-x
```
Если прав нет (например, файлы копировали вручную):
```bash
chmod +x scripts/relay/*.sh scripts/client/*.sh config/*.sh
```

Проверить права **в самом коммите** (на ПК, в репозитории):
```powershell
git ls-files -s scripts/client/wake_pc.sh   # → 100755 ...
```

## ✅ Проверка

**1. Скрипты на месте и исполняемые:**
```bash
cd ~/pc-remote-control && ls -l scripts/client/
```
→ у всех четырёх `-rwxr-xr-x`.

**2. Синтаксис (ничего не запускает, просто проверяет):**
```bash
bash -n scripts/client/wake_pc.sh && echo SYNTAX_OK
```
→ `SYNTAX_OK`

**3. Алиасы:**
```bash
type wake shutup reboot sleep
```
→ четыре строки `... is aliased to ...`.

**4. Первый реальный запуск:** `wake` при включённом ПК → `Magic packet sent to ...`.
Если пришло `❌ Домашний телефон не отвечает` — реле недоступно, смотрите [часть 6 → A](06-troubleshooting.md).

## ❌ Если не получилось

| Симптом | Причина и решение |
|---|---|
| `bash: wake: command not found` | `~/.bashrc` не применён: `source ~/.bashrc`, либо вы в другом шелле (проверьте `echo $SHELL`) |
| `❌ Домашний телефон не отвечает` | реле спит / Tailscale выключен / `sshd` на реле упал → [часть 6 → A](06-troubleshooting.md) |
| Команда «прошла», но ПК не выключился | пароль Windows неверный или `PC_USER`/`PC_IP` не те → запустите `bash -x` |
| `shutup` возвращает ошибку сразу | проверьте вручную цепочку из части 3.3 (проверка №2) |
| `sleep` не усыпляет ПК | на ПК отключён сон в электропитании, либо вложенный SSH без `-t` |
