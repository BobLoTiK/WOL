# 📱 Часть 2 — Домашний телефон (реле)

> **Где:** на домашнем телефоне — том, что остаётся дома и лежит в одной Wi-Fi сети с ПК.
> **Сколько времени:** ~20 минут.
> **Что должно получиться:** телефон принимает SSH на порту **8022** с основного телефона и умеет отправлять магический пакет ПК.

## Зачем нужен этот телефон

Реле делает **две** вещи, и обе невозможны с основного телефона:

1. **Будит ПК.** Магический пакет действует только внутри домашней сети — из интернета роутер его не пропустит.
2. **Служит трамплином.** ПК в домашней сети не виден снаружи (и это правильно), поэтому клиент заходит на ПК «через» реле.

Реле должно быть **всегда включено и в зарядке** — это его штатная работа.

---

## 2.1 · Ставим Tailscale

1. Установите **Tailscale** (Play Store; если его там нет — APK с официального сайта tailscale.com).
2. Войдите в **тот же аккаунт**, что будете использовать на основном телефоне.
3. Включите переключатель — в статусе должно быть `Connected`.
4. В настройках Android для Tailscale: **Батарея → Без ограничений**.

**Узнайте Tailscale-IP телефона** (понадобится в конфиге) — откройте Termux (следующий пункт) и выполните:
```bash
tailscale ip -4
```
Ожидается адрес вида `100.65.156.38` → это `RELAY_IP`.

---

## 2.2 · Ставим Termux и поднимаем SSH

> ⚠️ **Termux ставим только из F-Droid** (или GitHub releases). Версия из Google Play устарела и не работает с современными пакетами.

Поставьте **два** приложения из F-Droid: **Termux** и **Termux:API** (второе нужно для `termux-wake-lock`).

В Termux выполните по одной строке:

```bash
pkg update -y && pkg install -y python openssh termux-api
```

**Задайте пароль** — без него SSH-сервер не пустит даже вас:
```bash
passwd
```
Придумайте пароль и запомните его (он понадобится один раз, пока не настроите ключи).

**Запустите SSH-сервер и запретите Android выгружать Termux:**
```bash
sshd
termux-wake-lock
```

**Проверьте, что сервер слушает порт** (внутри Termux):
```bash
ss -tlnp | grep 8022
```
Ожидается строка с `:8022` — это и есть порт реле.

> ⚠️ В настройках Android для **Termux** тоже поставьте **Батарея → Без ограничений**, иначе система убьёт процесс.

## 2.3 · Кладём на реле скрипт `wol.sh`

Скрипт должен оказаться **именно в `~/wol.sh`** — клиент вызывает его по этому пути.

Содержимое (файл `scripts/relay/wol.sh` из репозитория):

```python
#!/data/data/com.termux/files/usr/bin/python
import socket

MAC = "10-FF-E0-90-FC-7D"        # ← MAC вашего ПК
BROADCAST = "192.168.1.255"      # ← первые 3 числа IP ПК + .255

mac_bytes = bytes.fromhex(MAC.replace("-", "").replace(":", ""))
packet = b'\xff' * 6 + mac_bytes * 16

sock = socket.socket(socket.AF_INET, socket.SOCK_DGRAM)
sock.setsockopt(socket.SOL_SOCKET, socket.SO_BROADCAST, 1)
sock.sendto(packet, (BROADCAST, 9))
sock.close()
print("Magic packet sent to " + MAC)
```

Что он делает: превращает MAC в 6 байт, добавляет 6 байт `0xFF` в начало и дублирует MAC 16 раз — это и есть «магический пакет» (102 байта). Отправляет его широковещательно на UDP-порт 9, поэтому пакет получают все устройства домашней сети, включая выключенный ПК.

**Два способа создать файл:**

1. **Скопировать с клиента** (когда часть 3 уже сделана):
   ```bash
   scp -P 8022 ~/pc-remote-control/scripts/relay/wol.sh <RELAY_USER>@<RELAY_IP>:~/wol.sh
   ```
2. **Вручную на реле:**
   ```bash
   nano ~/wol.sh      # вставить содержимое, Ctrl+O, Enter, Ctrl+X
   chmod +x ~/wol.sh
   ```

**Проверьте, что MAC и BROADCAST — ваши** (они отличаются от `PC_MAC`/`PC_BROADCAST` из конфига только форматом записи):
```bash
head -5 ~/wol.sh
```

## 2.4 · Автозапуск после перезагрузки телефона (рекомендую)

После ребута Android Termux закрывается, и `sshd` с `wol.sh` перестают работать — реле «умирает» до ручного вмешательства. Исправляется приложением **Termux:Boot** (F-Droid):

1. Установите **Termux:Boot** и **запустите его один раз** (иначе автозапуск не активируется).
2. В Termux создайте папку и скрипт:
   ```bash
   mkdir -p ~/.termux/boot
   nano ~/.termux/boot/start-sshd.sh
   ```
3. Содержимое:
   ```bash
   #!/data/data/com.termux/files/usr/bin/sh
   termux-wake-lock
   sshd
   ```
4. Сделайте исполняемым:
   ```bash
   chmod +x ~/.termux/boot/start-sshd.sh
   ```

Теперь после перезагрузки реле само поднимет SSH.

---

## ✅ Проверка

**1. На реле** (в Termux):
```bash
tailscale ip -4                 # → 100.x.y.z
ss -tlnp | grep 8022            # → строка с :8022
ls -l ~/wol.sh                  # → -rwxr-xr-x (исполняемый)
~/wol.sh                        # → Magic packet sent to XX-XX-...
```

**2. С основного телефона** (можно проверить и с ПК, если он в той же Wi-Fi):
```bash
ssh -p 8022 <RELAY_USER>@<RELAY_IP> 'echo OK'
```
Ожидается `OK`. Первый раз — `yes` на вопрос про отпечаток ключа и пароль, который задали через `passwd`.

> 💡 Если `OK` получен — реле готово. Магический пакет при выключенном ПК проверите в части 5.
> **Не забудьте** после проверки настроить ключи (часть 3.3), иначе каждая команда будет просить пароль.

---

## ❌ Если не получилось

| Симптом | Причина и решение |
|---|---|
| `Connection refused` с клиента | `sshd` не запущен: зайдите в Termux на реле и выполните `sshd` |
| `Connection timed out` | Tailscale не подключён, или вход в **разные** аккаунты, или телефон усыплён (проверьте «Батарея → Без ограничений») |
| `Permission denied` | не задан пароль (`passwd`) или введён не тот логин (`whoami` в Termux) |
| «Почему не 22 порт?» | В Termux SSH всегда на **8022**, порт 22 занят системой |
| `~/wol.sh: Permission denied` | забыли `chmod +x ~/wol.sh` |
| `~/wol.sh: bad interpreter` | файл сохранён с Windows-переводами строк; пересоздайте его через `nano` прямо на телефоне |
| После перезагрузки телефона ничего не работает | не настроен автозапуск — раздел 2.4 |
